# AGENTS.md

`AGENTS.md` 用于描述智能体：它是谁、帮助用户完成什么，以及回答或处理任务时应遵循哪些指引。开发者和智能体系统都可以阅读这份文件，了解项目的用途和行为边界。

在基于 Open Agent Format（OAF）的智能体项目中，它通常位于项目根目录。AIX 打包时可以保留这个文件，但 AIX 不会自行执行其中的指令。

## 写一份简单的描述

下面是一个天气助手的 `AGENTS.md` 示例：

```markdown
# 天气助手

帮助用户了解指定城市的天气，并提供简洁的出行提示。

## 工作方式

- 用户没有说明城市时，先询问需要查询的城市。
- 使用项目提供的天气数据回答，不要编造实时天气。
- 查询失败时，说明暂时无法获取结果，并提示用户稍后重试。
```

这份文件说明了助手的用途、处理信息不足时的方式，以及出错时如何回应。正文使用普通 Markdown；上面的标题只是帮助阅读的写法，不代表这些标题本身会自动开启功能。

## 应该写哪些内容？

可以从实际需求出发，说明下面几个问题：

- **职责**：智能体帮助用户完成什么任务？不处理什么？
- **处理方式**：信息不足时应该询问什么？什么时候需要用户确认？
- **回答方式**：结果应该详细还是简洁？遇到数据缺失或失败时怎样说明？
- **依赖和约束**：需要哪些服务或其他资源？哪些事情不能假设已经完成？

写得具体、可验证，并与项目实际实现的能力保持一致。例如，只有项目确实接入了天气服务，才能按服务返回的数据提供实时天气。

## 结构化信息与 OAF 资源

OAF 的 `AGENTS.md` 可以在 Markdown 正文前使用 YAML front matter，记录智能体身份及组合信息；它也可以配合技能、MCP 配置或子智能体等资源使用。具体字段、资源结构和约束请参考 [AIX Format Spec](https://yodaos-project.github.io/aix/spec?lang=en) 中的 OAF 基线与字段定义。

AIX 可以原样携带这些文件，但不会自动安装技能、启动 MCP 服务或执行模型策略。实际如何使用这些描述和资源，取决于智能体运行环境及应用集成。

## 它和 `app.json` 有什么区别？

| 文件 | 用途 |
| --- | --- |
| `AGENTS.md` | 描述智能体的职责、能力边界和行为指引 |
| `app.json` | 声明页面、Widget、后台任务和应用所需权限等配置 |

**在 `AGENTS.md` 中写明某项能力或权限，不会自动实现功能或授予权限。** 例如，使用摄像头时，还需要在 `app.json` 中声明所需权限、调用相应 API，并处理设备授权或不可用的情况。类似地，文中提及配置项或依赖，也不会自动创建环境变量或安装服务。
