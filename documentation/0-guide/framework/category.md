# 智能体交互的分类

想做一个天气助手：用户询问天气后，是在聊天中看一张卡片就够了，还是需要打开一个界面继续操作？AIUI 常见的交互形态可以从这两种方式来理解。

## 对话式 AIUI：在聊天中继续操作

对话式 AIUI 的界面出现在对话流中。用户提问后，智能体可以在当前对话里展示卡片、表单或结果；用户也可以直接查看信息、点击按钮或补充内容。

例如，用户询问天气，智能体返回一张天气卡片，用户继续在卡片中查看详情：

<in-chat-interaction-demo></in-chat-interaction-demo>

这种方式适合天气查询、搜索结果、行程确认等相对简短的任务。开发时，需要描述页面能做什么、适合什么时候使用，以及它需要哪些输入，让页面能够接收并展示相应内容。

## 沉浸式 AIUI：在独立界面中完成任务

沉浸式 AIUI 使用独立界面承载主要交互。用户可以围绕同一个界面查看状态、进行多次操作，并按应用支持的方式与 AI 协作。

例如，在斗地主界面中，用户可以持续查看手牌和牌局状态，再选择出牌或查看提示：

<standalone-interaction-demo></standalone-interaction-demo>

这种方式适合游戏、设备控制或需要持续反馈的任务面板。开发时，需要组织界面状态和操作流程；如果需要语音或模型能力，也要为相应功能接入所需服务。

## 应该选择哪一种？

- 希望用户在当前对话中快速查看或确认结果？从**对话式 AIUI**开始。
- 希望用户在一个界面里持续查看状态、完成多步操作？从**沉浸式 AIUI**开始。

两种方式也可以在同一个产品中配合使用。确定方向后，可以分别阅读[对话式 AIUI](../quickstart/first-chat.md)和[沉浸式 AIUI](../quickstart/first-immersive.md)，尝试创建示例。
