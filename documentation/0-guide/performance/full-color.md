# 全彩优化指南

全彩优化的目标是在 448 宽、最高 170 的内容区域内，让结果更容易读、操作更容易完成，并保持稳定运行。先按[全彩眼镜适配指南](/AIUI/guide/full-color)完成兼容，再依据[全彩视觉规范](/AIUI/design/visual-full-color)优化体验。

## 先减少信息，再调整排版

每个视图先回答一个主要问题，例如“现在是什么状态”“下一步去哪里”“这次任务是否成功”。把主要结果与必要操作放在首屏，辅助说明放入详情或后续步骤。

- 长段回答先显示摘要，再让用户进入详情或滚动阅读。
- 列表先展示当前最相关的条目，通过分页或滚动访问其余内容。
- 图表先展示关键指标或少量系列，保留标签和单位。
- 空态、加载态和错误态也要能在同一区域内读懂并继续操作。

不要把单色 480 × 352 的整页等比压缩进全彩区域。字号保持 14～24 dp，图标不小于 12 × 12，并为卡片外边距、内边距和描边保留空间。

## 用亮色表达重点

正文优先使用 `--color-text-primary`，次级内容使用 `--color-text-secondary`，少量重点使用主题强调色。保持同一状态的颜色语义一致，并配上文字或图标。

不要把所有内容都染成强调色，也不要通过增加大面积填充改善对比。纯黑会透明，深色细节容易消失；看不清时先减少噪声、提高前景亮度与 alpha，再到真机验证。

为边框、分割线与文字分别设置 alpha，避免卡片整体透明度叠加。默认描边 60%、选中 100%、分割线 40%；内容弱化时建议仍不低于 40%。

## 单独检查图片、图表和 Canvas

主题 Token 无法直接替换图片像素或 Canvas 中写死的绘图颜色。逐项检查这些资源：

| 内容 | 优化方向 |
| --- | --- |
| 图片 | 按实际展示尺寸准备资源，减少无关背景、暗色细节与图片内小字 |
| 图标 | 使用轮廓清晰、尺寸足够的资源；为单色与未知显示能力保留可读版本 |
| 图表 | 精简系列、网格和标签，优先线条与轮廓；不要仅用颜色区分关键数据 |
| Canvas | 随可用空间重新布局，明确设置可读字体、线宽和亮色；检查裁剪与标注 |
| 地图 | 保留必要路线、点位与标注，减少面状填色和不相关细节 |

不要在 170 高度中同时堆叠封面、长标题、多行正文、图表和页脚。拆成摘要与详情，或选择一个最能支持当前任务的展示方式。

## 保持操作与焦点可见

焦点应通过清晰的 100% 描边可见，不要只变换颜色。检查确认、返回和滚动是否能完成核心任务，尤其要确认长内容中的操作可以到达。

不要直接复用另一型号的镜腿按键假设。用目标设备验证交互；处理自定义按键前先明确默认行为，避免重复确认或吞掉返回。页面焦点与事件可参考[焦点系统](/AIUI/framework/open-agent-format-page-focus)和[页面事件](/AIUI/framework/open-agent-format-page-events)。

## 控制资源与更新频率

全彩并不意味着需要更多动画、图片或持续刷新。优先显示有效结果，装饰资源按需加载；不要为了全彩表现同时加载所有配色变体。

合并可以被新值替代的状态更新，避免流式输出每到一个字符就触发整页布局。限制列表和缓存长度；页面隐藏时暂停不必要的刷新、动画和媒体，卸载时释放监听与资源。具体方法见[运行时性能](/AIUI/guide/performance-runtime)和[启动性能](/AIUI/guide/performance-startup)。

## 用相同输入验证改进

记录目标型号、系统与运行时版本、智能体包版本、数据输入和测试场景。保持这些条件一致，再比较首屏、阅读、连续操作与长时间运行表现。

| 场景 | 检查重点 |
| --- | --- |
| 浅色与复杂真实背景 | 正文、次级文字、线条与焦点是否可辨 |
| 长标题、长文本、多条结果 | 是否超出 448 × 170，关键内容与操作是否仍可达 |
| 空态、加载、失败、重试 | 是否有明确说明和下一步，状态是否只靠颜色表达 |
| 连续滚动、切页、返回 | 焦点是否稳定，是否出现卡顿或后台任务持续运行 |
| 单色、全彩与未知能力回退 | 共用流程是否一致，是否仍有可读资源和必要操作 |

模拟器适合快速排查布局与逻辑；颜色、透视可读性、实际交互和性能应通过[真机调试](/AIUI/guide/debug-real_device_debug)确认。不要仅凭一次桌面预览或打包成功认定优化完成。
